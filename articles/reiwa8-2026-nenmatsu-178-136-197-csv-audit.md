## 2. 給与計算ソフト・自作スクリプトが踏む「6つの法定境界トラップ」

### トラップ①：`219万1,000円〜220万円未満` の措法29条の4第3項「階段調整」と別表第五の4,000円丸め

多くの簡易シミュレータが `max(740_000, int(salary * 0.3 + 80_000))` と書いてしまいますが、**年末調整（および給与収入660万円未満の確定申告）では所得税法第28条第4項により「別表第五」の適用が強制**されます。

さらに令和8・9年分では、租税特別措置法第29条の4第3項（国税庁 No.1410 注2）により、**収入 `219万1,000円〜220万円未満` に3段階の固定給与所得金額**が設けられています。

```python
def compute_employment_income_r8(salary_yen: int) -> int:
    """令和8年分・令和9年分 給与所得控除後の給与等の金額（国税庁 No.1410 / 別表第五・措法29の4完全準拠）"""
    if salary_yen <= 740_999:
        return 0
    if salary_yen < 2_191_000:
        # 74万1,000円以上〜219万1,000円未満は4,000円丸めなしの「収入 - 74万円」
        return salary_yen - 740_000
    if salary_yen < 2_193_000:
        return 1_451_000
    if salary_yen < 2_196_000:
        return 1_453_000
    if salary_yen < 2_200_000:
        return 1_456_000
    if salary_yen < 3_600_000:
        base_4k = (salary_yen // 4_000) * 4_000
        return (base_4k * 7) // 10 - 80_000
    if salary_yen < 6_600_000:
        base_4k = (salary_yen // 4_000) * 4_000
        return (base_4k * 8) // 10 - 440_000
    if salary_yen < 8_500_000:
        return (salary_yen * 9) // 10 - 1_100_000
    return salary_yen - 1_950_000
```

この1円単位の実装により、国税庁パンフレット記載の境界値である **`475万1,999円`（合計所得 `335万8,400円 <= 336万円`）vs `475万2,000円`（合計所得 `336万1,600円 > 336万円`）** や **`665万5,556円`（合計所得 `489万円ちょうど`）** が1円の狂いもなく一致します。

### トラップ②：令和8・9年分の基礎控除 `104万円` は「合計所得489万円（年収約665.5万円）以下」まで全員対象

「178万円の壁（基礎控除104万＋給与所得控除74万）」という見出しだけを追っていると、`104万円` の基礎控除が低所得層限定だと錯覚しがちです。

しかし国税庁タックスアンサー No.1199（租税特別措置法第41条の16の2）の令和8・9年分欄を確認すると、特例加算（本則62万円＋42万円）により **合計所得金額 `489万円以下`（給与収入のみの場合は `665万5,556円以下`）まで一律 `104万円`** となっています（令和10年分以後は132万円超が62万円へ戻る時限設計）。

- 合計所得 **`489万円以下`**（給与 `665万5,556円以下`）：**`104万円`**（令和7年分は `95万` / `88万` / `68万円`）
- 合計所得 **`489万円超〜655万円以下`**（給与 `〜850万円以下`）：**`67万円`**（令和7年分は `63万円`）
- 合計所得 **`655万円超〜2,350万円以下`**：**`62万円`**（令和7年分は `58万円`）

特に合計所得 `336万超〜489万円以下`（額面年収 約476万〜665万円）の正社員層は、基礎控除が昨年の `68万円` から **`104万円`（`+36万円`）** へ一気に跳ね上がります。基礎控除申告書のテンプレートや転記ロジックに昨年の区分が残っていると、中堅社員全員で過大徴収（還付漏れ）が発生します。

### トラップ④：「年収 `123万超〜136万円以下`」の特定扶養復帰 ✕ 所得金額調整控除（最大15万円）の連鎖

ここが令和8年分年末調整で最も見落とされやすいプロ向け論点です（国税庁Q&A `Q2-1`・`Q2-4`）。

19〜22歳の子が給与 `130万円` の場合：
- 年初（令和7年基準：給与控除65万・扶養上限58万）では、所得 `65万円 > 58万円` だったため「控除対象扶養親族」から外れ、「特定親族」扱いでした。
- しかし **令和8年12月1日改正後** は、`130万 - 74万 = 56万円 <= 62万円` となるため、**「特定親族」ではなく通常の『控除対象扶養親族（特定扶養親族）』へ復帰**します。

「どちらも控除額は63万円だから同じでは？」と思うと危険です。
**『特定扶養親族（＝23歳未満の扶養親族）』に復帰すると、給与収入850万円超の親に『所得金額調整控除（最大15万円、措法41の3の11）』および『新生命保険料控除の一般枠6万円拡充特例』が同時に復活**します（「特定親族」のままでは「扶養親族」ではないため所得金額調整控除の対象になりません）。

## 3. 復興特別所得税（102.1%）と端数処理・Shift-JIS CSV 検算の実装

年末調整の年調年税額計算では、浮動小数点誤差（`float` の丸めずれ）を避けるため、Python でも JavaScript でも**完全整数演算**で実装するのが鉄則です。

```javascript
// 課税給与所得金額（1,000円未満切捨て）→ 算出所得税額 → 住宅ローン控除 → 102.1%（100円未満切捨て）
export function computeNationalIncomeTax(taxableIncomeRawYen, housingLoanCreditYen = 0) {
  if (taxableIncomeRawYen <= 0) return 0;
  const rounded = Math.floor(taxableIncomeRawYen / 1000) * 1000;
  if (rounded < 1000) return 0;

  const brackets = [
    [1949000, 50, 0],
    [3299000, 100, 97500],
    [6949000, 200, 427500],
    [8999000, 230, 636000],
    [17999000, 330, 1536000],
    [39999000, 400, 2796000],
    [null, 450, 4796000],
  ];

  let baseTax = 0;
  for (const [upper, permille, quickDed] of brackets) {
    if (upper === null || rounded <= upper) {
      baseTax = Math.floor((rounded * permille) / 1000) - quickDed;
      break;
    }
  }
  const netBaseTax = Math.max(0, baseTax - housingLoanCreditYen);
  // 102.1% = 1021 / 1000、さらに100円未満切捨て ＝ 整数除算 floor(netBaseTax * 1021 / 100000) * 100
  return Math.floor((netBaseTax * 1021) / 100000) * 100;
}
```

この式を使うと、たとえば課税給与所得 `1,000円`（本人年収 `1,781,000円`・社保0円）のとき `算出税額 50円 × 1.021 = 51.05円` が100円未満切捨てで `0円` となり、`1,782,000円` で初めて `100円` になる実務上の挙動まで完全に一致します。

また、経理現場の給与ソフトから出力される CSV は `Shift-JIS (cp932)` と `UTF-8 (BOM付/なし)` が混在するため、ブラウザ側では `TextDecoder("utf-8", { fatal: true })` から `TextDecoder("shift-jis", { fatal: true })` へフォールバックさせ、出力時は `\uFEFF`（UTF-8 BOM）を先頭に付与することで、Windows / Mac の Excel で文字化けゼロのまま直接開けます。
